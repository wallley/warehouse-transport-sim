# 原算法与实现限制

本次整理以保留课程原实现为目标，拆分模块并补足构建、运行和文档入口。下面区分代码实际行为与[课程要求](COURSE.md)，方便阅读、复现和后续修改。

## 调度策略

空闲车辆定期扫描货物已经就绪的订单，选择沿轨道正向行驶距离最近的取货点。分配后更新订单和车辆状态，避免其他车辆重复领取同一订单。同一来源设备通过队列维护任务先后顺序。

这是集中式主循环中的最近距离贪心策略。它没有全局求解最短总耗时，也没有为任务紧急程度、拥堵预测、目标站点等待时间或多车联合路线建立优化目标。没有订单可接时，车辆可能随机移动到站点，减少原实现中的长期等待。

本仓库不据此声称全局最优、分布式调度或已经证明的吞吐提升。历史课程报告中的性能表、百分比和未核实算法描述没有作为当前版本的性能结论发布。

## 整理时修复的运行生命周期

运行状态改为由每个仿真上下文持有。开始新一轮仿真时，先关闭上一轮日志，清零时钟与完成标记，重置随机状态和调度日志缓存，再初始化站点与车辆。打开新一轮日志之后，记录初始已经准备好的来源站点货物状态，避免重复运行时遗留上一轮时间和状态。

输出路径集中到配置目录，运行文本采用 UTF-8，图形与无图形入口使用同一套初始化和单步接口。这些修改解决模块拆分及多轮运行中的状态、日志问题，没有改变上面的最近距离调度目标，也没有修复下面列出的原课程物理近似。

## 课程约束与保留行为

| 项目 | 课程要求 | 保留的程序行为 |
| --- | --- | --- |
| 初始车距 | 车身净距 200 mm，即 2000 mm 车长下中心距为 2200 mm | 初始化中心距为 5200 mm，由车长 2000、`SAFETY_GAP_MINIMUM` 2200 和额外缓冲 1000 相加得到 |
| 跟车缓冲 | 车身净距至少 200 mm | 跟车逻辑将 2200 mm 作为车身前后净距的基础缓冲，并叠加制动项 |
| 巡游停车 | 三车随机在出入库口停车 | 三车的目标站点固定为 13、15、18，目标速度随机生成 |
| 巡游圈数 | 完整巡游一圈 | 超过轨道长度的 70% 后设置圈数标记，再向指定站点行驶；该标记不证明已完整行驶一圈 |
| 到站运动 | 按加减速规律停止 | 接近目标时会将位置吸附到站点，并直接将速度清零，存在离散运动近似 |
| 弯道限速 | 弯轨速度不超过 40 m/min | 进入弯道后降低目标速度，再以 500 mm/s² 逐步减速；实际速度在过渡期间可能高于弯道限速 |
| 运行日志命名 | `TaskExeLog.txt`、`DeviceStateLog.txt` | 文件名带车辆数或 `Patrol` 后缀，便于区分运行配置 |
| 布局改进 | 分析布局改进效果 | 保留既有场景布局；未把报告中的布局设想实现为独立优化方案 |

已有跟车控制基于前车距离、制动距离和速度限制进行调节。车身已经重叠时，负间距可能在环形位置归一化后被解释成长环距，无法保证识别重叠并制动。因此，这套启发式控制不能作为严格防碰撞保证；逐帧车辆更新、弯道限速切换和到站吸附也需要在进一步研究中单独评估。

`generateScheduleReport` 会将站点最后一段状态时间累计到统计字段。当前入口通常每轮只生成一次报告；对同一个运行状态多次调用，可能重复计入末段时间。报告函数不适合作为可重复调用的统计测量接口，需要重复分析时应重新运行，或先改为不修改模型状态的统计计算。

## 随机数与复现

无图形入口记录随机种子及最终生效配置。核心使用与原 MSVC `rand()` 相同的序列机制，在相同版本、相同参数及相同运行入口下，可以用固定种子重复运行。

图形界面的粒子和字符雨沿用旧效果，并与仿真共享上下文中的随机状态。开启界面、不同渲染帧数或特效设置可能消耗不同数量的随机数。因此，同一个种子不保证 GUI 与 CLI 的轨迹一致，也不保证修改代码后的不同版本保持逐步一致。比较调度变化时，应固定 CLI 入口、种子、车辆数和时间步长。

## 如何理解验证

构建和核心测试检查工程是否能运行及选定行为是否符合预期；原版对照用于检查拆分是否保留状态转换，运行步骤见[原版算法对照](USAGE.md#原版算法对照)。它们不等于证明程序已经满足所有课程物理约束，也不等于获得真实仓储系统的工程验证。

README 中的界面图来自程序渲染，仅用于展示界面。仓库不附旧运行日志、报告成绩或性能结果文件；如需比较车辆数量，请自行运行，保存参数，并检查所有订单是否完成、运行是否达到时间上限。

## 可以继续改进的方向

- 先统一车身净距与车辆中心距的定义，再检查初始车距和跟车阈值。
- 将巡游一圈判定改为实际累计距离，并明确随机停靠规则。
- 改进到站和入弯制动，避免速度瞬时改变，并增加物理约束检查。
- 分开仿真与界面的随机数，减少渲染对任务轨迹的影响。
- 在固定输入和种子的条件下比较不同调度策略、布局与车辆数量。

这些是后续研究方向，当前仓库没有把它们列为已经实现或验证的优化。
